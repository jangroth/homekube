# Agent Vault brokers agents' API credentials; the Infisical operator syncs secrets

Agents reach external APIs through Infisical Agent Vault, an HTTPS proxy in namespace `agent-vault` that injects credentials, so the agent never holds them. The exception is Hermes's control-plane credentials, which the proxy can't carry, held by Hermes itself: its Coder token (`coder ssh` uses WebSockets, and coderd is in-cluster), kept narrow by API-token scopes and a non-Owner user ([#105](https://github.com/jangroth/homekube/issues/105)); and its Agent Vault machine identity, which mints the sessions the proxy grants, kept narrow by the Member role and grants on per-repo bundles only ([#107](https://github.com/jangroth/homekube/issues/107)). Secret sync into the cluster uses the Infisical operator with Kubernetes Auth, not External Secrets Operator. Infisical validates the client's own service-account token (no reviewer JWT), so the operator has no credential to seal. Each app has its own machine identity, bound to one service account in its own namespace and limited to that app's secrets, keeping the per-namespace isolation sealed secrets gave. Each app's secrets are their own Infisical project, read with the built-in Viewer role, because path-scoped custom roles are Enterprise-only; brokered credentials sit in a separate project only Agent Vault can read.
